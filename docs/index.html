The paper in 60 seconds

Question. An assistant knows thousands of small facts about you. To answer a question that needs a chain of 2-10 of those facts, should the facts be looked up (explicit memory, RAG) or trained into the model (implicit memory, LoRA)?
How they test it. They build a synthetic benchmark (MPR) from a knowledge graph per user, then compare 4 retrievers, 2 fine-tuning methods and a hybrid, under 4 reasoning styles.
Answer. Look it up. Explicit memory wins clearly; implicit memory alone is near useless; their hybrid (HybridMem) adds only about 0.01-0.03. Iterative retrieval (chain of thought) helps most.

Glossary use these words consistently on your slides

Statement / fact
One sentence about the user, e.g. "Alice's husband is Bob". Each user has about 13.1k. The set is called S.
Hop
One link in the reasoning chain. A 4-hop question needs 4 links; no single fact gives the answer.
Gold facts
The facts that are really needed for a question (the benchmark stores them, so it can measure retrieval).
Explicit memory
Facts stay as text; a retriever fetches the most relevant ones at question time and the LLM reads them (RAG).
Implicit memory
Facts are fine-tuned into the model weights (here with LoRA), so the model answers from its weights alone.
BM25 (SparseRAG)
Keyword retrieval: scores facts by shared words, weighted by rarity.
e5 (DenseRAG)
Embedding retrieval: scores facts by cosine similarity of meaning vectors.
LoRA / SFT
Supervised fine-tuning that trains only a small low-rank add-on ("adapter") to the model.
AskSFT / MaskSFT
Two ways to turn facts into training data: generate QA pairs from each fact, or hide an entity and train the model to fill it in.
HybridMem
The paper's method: k-means clusters of facts, one LoRA per cluster, and a vote over retrieved facts picks the adapter.
Oracle / Ignoramus
Upper and lower baselines: given exactly the gold facts, or given no memory at all.
NR / SR / MR / DR
Reasoning styles: one call; chain of thought with re-retrieval; tree of thought; decompose into sub-questions.
EM
Exact Match accuracy after normalising case and punctuation.

1The problem: multi-hop personal memory

A personal assistant stores many small facts. A real question often needs several of them chained together:

Which city does Alice's husband's boss work in? needs Alice → husband → Bob→ Bob → boss → David→ David → office → New York

Two things make this hard at the same time:

  • Memory problem. A retriever only sees the question. The fact "David's office is in New York" shares no words with "Alice's husband's boss", so a single search misses it. For fine-tuning, the question is whether a small adapter can store 13k precise facts at all.
  • Reasoning problem. The model must chain the facts step by step, and ideally search again after each step.

Older personalization benchmarks (LaMP, PerLTQA, LongMemEval) mostly test style or 1-2 hop lookups. MPR goes to 10 hops.

Why can't one search with the question find every fact for a 6-hop question?

2How the benchmark is built

This is the most "data mining" part of the paper: a knowledge graph per user, random walks to sample reasoning paths, and an LLM to turn graph edges into text.

  1. Meta graph: 108 entity/attribute types and 34 relation types. Some edges are "value" edges (arithmetic or date steps such as +270 days).
  2. Per-user graph: an LLM fills in values. 12 users, about 5.9k nodes each.
  3. Statements: each non-value edge becomes one sentence, about 13.1k per user. This is the memory S.
  4. Random walk of k = 2..10 edges gives a reasoning path.
  5. LLM rewriter turns the path into one natural question; the answer is the path's end node.

The released data has 2,700 questions per user (300 per hop), 32,400 in total, 9 MB.

Why does a model with no memory still score 20-27% on long-hop questions?

3Three kinds of memory

Explicit
Retrieve the top-k facts (k = 20), then answer.
â = LLM(RAG(q, S) ‖ q)
Retrievers: BM25, e5, a MemTree-style tree, GraphRAG.
Implicit
Fine-tune on the facts, then answer from weights only.
θ̂ = SFT(θ; S), â = LLMθ̂(q)
LoRA r=8, 10 epochs.
HybridMem
Embed facts, k-means into 50 clusters, one LoRA each. At question time, retrieve, map each fact to its cluster, majority-vote the adapter, answer with adapter plus facts.

Link to your earlier talk: HybridMem uses clustering to split memory into blocks. A natural extension slide is "what if we used agglomerative clustering instead of k-means?"

In HybridMem, what decides which LoRA adapter is loaded?

4Four reasoning structures

The key idea is in SR: after each thinking step, search again using the latest thought as the query (Ŝi = RAG(oi-1, S)). That is how the chain reaches facts that never matched the original question.

6What we re-ran

Four cheap experiments cover the "re-run / re-implementation" requirement. Total cost: about 1.7k LLM Farm calls, no paid GPU.

6a · Retrieval probe (no LLM, instant, best live demo)

For user 0's 2,700 questions, what fraction of gold facts does one top-20 search find? This reproduces the paper's "dense short, sparse long" pattern from retrieval alone. BM25 takes 2 s; e5 takes 62 s on the laptop GPU.

6b · Leak check (all 32,400 questions)

Share of questions whose text restates a number from one of their own gold facts. Example (hop 7): "...popularity index of 87... What is the value after adding 5 to 87 minus 12?" The answer (80) needs no memory.

Reproduced: Oracle ≫ RAG ≫ no memory, and BM25 beats e5 on hops 8-10 (0.40 vs 0.13). Different from the paper: SR adds little over NR here, likely because gpt-6-luna already reasons internally. Only 15 questions per bucket, so read only the big gaps.

6d · Implicit memory in miniature (Qwen2.5-0.5B, laptop GPU)

The paper's 7B fine-tuning cannot fit a 6 GB laptop, so we tested single-fact recall instead: can the model answer about facts it was fine-tuned on?

  • LoRA alone recalls at most 11% of the exact facts it trained on.
  • Retrieval lifts the same model from 0% to 67%.
  • LoRA + retrieval is no better than retrieval alone, and worse on reworded questions: the paper's story in miniature.

7Critique: your own findings

This section turns the talk from a summary into analysis. Each point has evidence you produced.

Dataset leakage. 61% of 10-hop questions restate a value of 3+ digits from their own gold facts (82% counting any number). No-memory accuracy of 20-27% on hops 5-10 is partly arithmetic on the question text. Fix to propose: re-score on a leak-free subset.
HybridMem effect within noise. Gains of about ±0.01-0.03 with no variance or significance tests; some cells get worse. "Consistently improves" is overstated.
Missing code pieces. No LLM server, no scorer, no dataset-generation code, no license. HybridMem crashes on its first run (Adapter 1 not found), and by default it loads the epoch-1 checkpoint.
Training setup issues. Prompts are padded to 4,096 tokens (about 90× wasted compute), and the train and test prompt formats differ. Our ablation shows the padding is a minor factor (recall 0.07 → 0.11).

9Questions the teacher may ask

Try answering each one aloud before you open it.

Why is this a data-mining paper and not just an NLP paper?It builds a benchmark by sampling paths from a knowledge graph with random walks, evaluates information retrieval (BM25 vs embeddings), and its own method is k-means clustering plus per-cluster models. The talk is about evaluation methodology and data quality, including the leakage we found.
Why does implicit memory fail?A small LoRA adapter trained for a few epochs cannot store thousands of precise facts. The paper also finds fine-tuning hurts multi-step reasoning. Our 0.5B probe shows at most 11% recall even on the exact training questions.
Why might BM25 beat embeddings on long hops?A likely explanation: long questions contain exact entity names and values, which keyword search matches precisely, while one embedding of a long question blurs many topics together. We checked one alternative explanation: leaked numbers do not cause it, because recall is similar with and without a leak.
Your numbers differ from the paper's. Why?Different model (gpt-6-luna vs Qwen2.5-7B), a 45-question subset rather than 2,700, and no 7B fine-tuning. We compare trends, not absolute numbers.
Is HybridMem worth using?Not on this evidence: the gains are about 0.01-0.03, with no variance reported, and some settings get worse. Retrieval alone gets almost all the benefit.
What would you change in the benchmark?Remove or flag questions that restate intermediate values, report variance across users, and release the dataset-generation and scoring code.

Slide-ready summary

  1. Explicit memory wins, and the ordering reproduces. EM for no memory / BM25 / e5 / Oracle: 0.041 / 0.114 / 0.109 / 0.257 with one call (900 questions) and 0.056 / 0.193 / 0.222 / 0.513 with a 5-step chain (306 questions). No memory, RAG and Oracle are separated by non-overlapping 95% intervals.
  2. Searching again helps, then plateaus. 5-step chain minus one call, same 306 questions: BM25 +0.078 [+0.033, +0.124], e5 +0.095 [+0.049, +0.137]. No step count above 3 beat 3 steps (2, 3, 5, 8 steps tested).
  3. "Dense for short hops, BM25 for long hops" holds for retrieval, not for answers. Recall@20 of gold facts, 32,399 questions: hop 2 e5 0.997 vs BM25 0.877; hop 10 BM25 0.340 vs e5 0.284. In answer EM the two retrievers are not separable (e5 minus BM25 -0.006 [-0.027, +0.016]).
  4. More retrieved facts did not help here. From k = 10 to 50 recall of BM25 rises 0.376 to 0.595 but EM stays flat (0.123 to 0.116). The paper's top-k pattern is not reproduced (one-call runs only).
  5. HybridMem: not reproduced at toy scale, and small in the paper itself. With a 0.5B model it did not beat plain retrieval in 4 of 4 retrieval conditions. In the paper's own Table 3 the mean change over 40 cells is +0.002 (23 cells up, 15 down, 2 tied), against the claim that it "consistently improves".
  6. The benchmark leaks. 53% of all questions restate a number from their own gold facts (82% at 10 hops). No-memory EM is 0.065 [0.042, 0.088] on those, 0.014 [0.005, 0.026] on the leak-free rest.
  7. What this does not cover. Of 17 claims: 3 reproduced, 7 partially, 2 not reproduced, 5 not tested (MR and DR reasoning, TreeRAG, GraphRAG, the 3B model, 7B LoRA and the SFT-hurts-reasoning claim). Absolute numbers are lower than the paper's.

Threats to validity

  • Different model and precision. 4-bit AWQ Qwen2.5-7B-Instruct with greedy decoding on a T4, against the paper's Qwen2.5-7B on A800s. The paper's text does not state precision or decoding; upstream's API path hard-codes temperature 0.9 (upstream-notes.md, item 3). Absolute numbers are not comparable; orderings and signs are what we test.
  • Our own scorer. Upstream ships no scorer (docs/upstream-notes.md, item 2); ours is SQuAD-normalised EM. The paper's normalisation may differ.
  • Our own runner. The T4 grids use a thin runner (experiments/_shared/grid.py) with the upstream NR and SR call flow and prompt templates, not upstream's run_qa.py; only the 9-question farm run used the original script.
  • Small slices, one seed. 900 questions (100 per hop) and 306 (34 per hop) against the paper's 2,700, one draw (seed 0) over all users. Per-hop values are coarse, and differences below about 0.04 are not visible, so several "no detectable effect" results (top-k, steps) are absence of evidence, not evidence of absence.
  • Intervals are narrow in one respect only. They are bootstrap intervals over questions: no variation over seeds, users, models or sampling. Many paired comparisons are uncorrected for multiple testing.
  • Leaked numbers. Over half of all questions restate a number from their gold statements, which inflates no-memory scores and distorts the hop curves (row 2, row 7). We report leak-free scores next to the full ones where the summaries have them; the paper does not.
  • Runs not made together. The 5-step chain (306 q) is from a different VM and day than the 2/3/8-step runs; the farm run (9 questions, a different model) and the scout's 45-question run are context only and carry no verdict here.
  • Implicit and hybrid at toy scale. 0.5B model, 300 facts, 5 clusters, 60 + 60 non-independent probe questions, farm-written training pairs and a single-fact probe: it tests the idea, not the paper's 7B results, and no 7B LoRA, MaskSFT, TreeRAG or GraphRAG was run.
  • Paper side. Only arXiv v1 was checked; the KDD camera-ready may differ. Figures 3-6 and 8-10 have no numeric table, so any claim resting on a chart is compared by its text statement only, not by values. The paper is internally inconsistent in places (10,800 vs 108,000 QA tasks, p. 4; TF-IDF in §4.1 vs BM25s in §3.4.2).
