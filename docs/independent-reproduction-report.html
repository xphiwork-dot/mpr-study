Multi-Hop Personal Memory: What Actually Works?

When an AI assistant stores 13,100 private facts about a person, how should it remember them and chain clues together? We reproduced Zhang et al.’s MPR repo (nuster1128/MPR @ a24953c) on a Tesla T4—including all 612 rows of Multi-path Reasoning (MR)—to separate real gains from wasted compute.

1 · Verdict in 60 Seconds

Simple 3–5 Step Search Wins; Tree Search & LoRA Don’t Pay Off

Simple 3–5 step search-and-think (SR) nearly doubles 1-shot RAG accuracy, while 12-call tree search (MR) wastes 2.4× compute for the same score. Store personal facts as searchable text—not LoRA weights—and filter out leaked numbers when scoring high hops.

✓ Holds Up

Confirmed in Reproduction

  • Explicit text beats closed-book: RAG beats no-memory guessing across all 900 tested questions.
  • Iterative loops double EM: SR adds +7.8 to +11.8 pp on RAG and lifts Oracle 25.5% → 51.3%.
  • 3 steps is the sweet spot: Accuracy peaks at 3 steps (22.9% BM25, 24.5% e5) then plateaus.
  • LoRA can’t store 13k facts: Closed-book SFT recalls almost nothing and hurts multi-hop reasoning.
⚠ Caveats

True Only in Part

  • BM25 and e5 tie on answers: Raw recall crosses over by hop, but final answer EM is tied.
  • Why SR beats NR: Oracle gains +25.8 pp without re-retrieval—multi-turn math drives half the lift.
  • “No shortcuts” misses numbers: Names are hidden, yet 53% of prompts leak private gold numbers.
✕ Does Not Hold

Refuted or Overstated

  • 12-call MR beats SR: Paired deltas are zero (+1.0 pp BM25, -0.7 pp e5; 95% CIs straddle 0).
  • Bigger top-k lifts EM: Growing k 10 → 50 boosts recall +25 pp, but EM stays flat (~11–12%).
  • HybridMem improves RAG: Crashes out-of-the-box (BlockSFT bug) and averages +0.2 pp in Paper Table 3.
2 · How the Methods Actually Work

Why 12-Call Tree Search Collapses to Shallow Depth 1–2 Paths

Paper diagrams show MR exploring a deep 5-step tree, but upstream StructuredReason.py never removes shallow parent paths and picks branches without retrieving user facts. Faced with unverified deeper chains, the model picks a depth 1 or 2 path 74.5% of the time.

Visual 1 · Control Flow & Observed MR Depth (n = 612 runs)

1-shot RAG vs. 5-step entity chasing vs. 12-call append-only buffer

  • Unpruned buffer (line 45): path_buffer[:pid] + path_buffer[pid:] + new_path_list copies every old shallow path forward.
  • Blind selector (lines 34, 48): All 4 selection calls run without retrieved facts, favoring short paths (99.7% genuine choices).
  • Redundant branches: Both children receive the exact same prompt—producing 32.3% word-for-word duplicates even at T = 0.7.

Middle-round identical branch pairs: 296 / 918 (32.2%) on BM25 and 297 / 918 (32.4%) on e5; selector parser fallbacks occurred in just 0.25%–0.33% of calls.

Compute footprint (612 rows on 1× Tesla T4): 5-step SR used 3,060 calls, 2.27M prompt tokens, and 39.8 min. 12-call MR used 7,272 full-stage calls, 5.15M prompt tokens, and 75.2 min (+ 6.2 min smoke).

What about DecompositionReason (DR, 3–7 calls)? DR splits the question into ≤5 sub-questions without RAG, answers each sub-question with RAG, then merges. S6 DR is currently running in a separate worker on s306; the paper notes it trails SR due to “initial decomposition myopia.”

3 · Paper Claims vs. Our Reproduction

Iterative SR Jumps +8–10 pp; 12-Call MR Adds Nothing

On 306 matched questions (Qwen2.5-7B-Instruct-AWQ, single T4, k = 20), 5-step SR beats 1-shot NR by +7.8 to +9.5 pp, while 12-call MR ties SR within ±1 pp. Even in the paper’s own Table 3 (8× A800), MR trails SR on 7 of 8 explicit-memory cells.

4 · Hidden Code & Benchmark Surprises

Why High Hops Look Artificially Good—Plus 4 Upstream Bugs

At hop 10, top-20 pulls all required facts in ≤1.6% of queries—yet accuracy bounces upward on hops 8–10. That happens because LLM question rewrites leaked private numbers into 82% of 10-hop prompts, letting models solve date math without memory.

Visual 4 · Retrieval Collapse vs. Rising Prompt Number Leakage (32,399 Qs)

Full-chain retrieval falls below 6% on hops 7–10 while number leakage climbs to 82%

Dataset Count & Hop Mismatch Data

Paper claims 108,000 QAs (or 10,800 in text); actual release has 32,399 QAs, and 10-hop queries need ~6.5 facts.

Missing e5 Query Prefixes DenseRAG.py

e5-base-v2 requires "query: " and "passage: " prefixes, but upstream embeds bare strings without either.

HybridMem Crashes on Load BlockSFT.py

Saves LoRA adapters as "default", then calls set_adapter(str(cluster_id))—raising an immediate ValueError.

90× Wasted SFT Padding utils.py:159

Pads ~45-token prompts out to 4,096 tokens during SFT, training answers at position 4096+ while testing at ~50.

1. QA Counts & 6.5 Statements Dataset

Public release has 32,400 rows (2,700 × 12 users, minus 1 null in User 8 hop 4 = 32,399), vs. 108,000 in Tables 1–2 and 10,800 in §3.3.3. Value hops lack user statements, averaging ~6.5 unique statements at hop 10.

2. Number Leakage (53% Overall) Benchmark

53% of 32,399 Qs share ≥1 number with gold facts (82% at hop 10; 38% overall / 62% at hop 10 for 3+ digit numbers).

3. Identical MR Prompts & eval() StructuredReason.py

Lines 37–44 ignore branch_id, feeding identical prompts to both branches; lines 13–14 run raw Python eval() on LLM output.

4. Missing e5 Prefixes & BM25 Label DenseRAG.py:23

Omits mandatory query:/passage: prefixes for intfloat/e5-base-v2. Also, §4.1 calls SparseRAG “TF-IDF” while code uses bm25s.

5. 4,096-Token SFT Left/Right Pad utils.py:159

Pads every ~45-token prompt to 4,096 tokens + 512-token answer (4,608 tokens/sample), wasting ~90× compute and shifting RoPE positions.

6. BlockSFT Adapter Bug & Epoch 0 BlockSFT.py

Saves adapters under "default" then calls set_adapter(str(cluster_id)); config loads lora_load_index: 0 (epoch 1 vs. §6.5’s epoch 7).

7. AskSFT Train/Test Mismatch BaseMethod.py

Trains on bare questions (with ~28% duplicate QA pairs) but tests with Naive_Ignoramus wrappers—dropping 0.5B probe recall from 7–11% to 0–2%.

8. Missing Scorer, Server & License Repo Hygiene

No Exact Match scorer, no local Qwen server (hard-codes external HTTP endpoint), missing scikit-learn/accelerate in requirements, and no license.

5 · Practical Takeaway & Conclusion

What to Build With Today

To answer multi-hop questions over personal data, pair a plain text index with a 3–5 step search-and-think loop (SR). You capture the paper’s full accuracy gain while avoiding 2.4× tree-search overhead and brittle per-user LoRA training.

1

Use 3–5 Step Iterative RAG (SR)

Nearly doubles 1-shot accuracy (22.9%–24.5% at 3 steps) at one-quarter the call cost of 12-call MR.

2

Chase Entities, Don’t Bloat top-k

Rewriting queries at each hop works; stuffing 50 loosely matched facts into 1 call gives zero lift.

3

Keep Episodic Facts Out of LoRA

Text indexes update instantly, whereas SFT forgets exact dates and degrades reasoning by 6.0–9.5 pp.

4

Audit Benchmarks With a No-Memory Baseline

If closed-book accuracy rises on harder hops, synthetic prompts are leaking answers—always report a clean slice.
